# Risk Register

> All risks with evidence and mitigations: vendor bundling, OpenShell as default data plane, the broker's own bugs, credential honeypot, misuse within scope, Seatbelt removal, Linux platform variance, TLS breakage (pinning, QUIC, ECH), learned-policy over-grant, approval fatigue, upstream scoping limits, vendor hook instability, buyer budget.

## Summary

Every risk the record names, with its evidence, a likelihood and impact rating, the mitigation, and the signal that should make the owner act. The **evidence** and **mitigation** columns come from the report's risk table and research note 05 section 5.5. The **likelihood**, **impact** and **trigger** columns are **Proposal** judgements for the build team, not sourced facts; re-rate them at every milestone exit and record changes in [[Build Log]].

Scale: likelihood and impact are High / Medium / Low over the next 12 months.

## Implications for the build

- R3 is the risk the build controls most directly: no parser without a fuzz target, no adapter without conformance probes.
- R5 constrains wording everywhere: CLI output, docs and code comments must not claim the broker stops injection.
- R9 means the learner's safeguards are part of M2's acceptance, not optional hardening.

- Whether any vendor exposes a stable egress hook the broker could use instead of wrapping.
- Real-world TLS-pinning breakage rates for common dev tools (missing from the record).

## Implementation notes

### M4 risk walk (2026-10-01)

The **Status** column was added by this walk. Likelihood and impact changes are shown as old → new; every other rating was re-checked and left as it was. A mitigation counts as built only where code and a test exist. Evidence per row:

- **R1.** Exporters: `m2_exporters::exports_match_the_golden_files` (six profiles × two targets). Minting: CI job `real-github` (a real GitHub App, every push) and `m3_s3::d6_*` (fake STS and S3; D6 against a real AWS account is outstanding). Identity: CI job `ci-mode` (a real Actions OIDC token), `m3_login::*` (stand-in IdP; Okta and Entra tenants outstanding). Profiles ship for Claude Code, Codex, Cursor agent and Gemini CLI (`code/profiles/`), but [[M0 Contained Run]] acceptance A1 has run in 1 of 8 agent × OS cells (Claude Code, macOS 26). No design partner exists, so the partner trigger cannot fire yet.
- **R2.** No OpenShell code in `code/`; [[ADR-025 Native Config Exporters as Built]] leaves OpenShell and Cursor exporters to phase 2.
- **R3.** Defects found in our own enforcement or record since 2026-09-24, each fixed with a regression test (sources: [[Build Log]], the ADRs named):
  - canonicaliser and parsers (11): three `paths`-rule bypasses (`..;/`, overlong UTF-8 dots, a malformed escape; `m4_differential::cat8_no_allowed_request_reaches_outside_its_path_rule`, fuzz target `path_differential`); host canonicalisation not a fixed point for a soft hyphen before an A-label (first nightly run); `RepoId` treating `Web.GIT` and `web` as different repositories (fuzz smoke); hyper's `max_buf_size` not bounding request heads on TLS streams; gzip bodies with a second member read only in part; method-override headers that could turn an allowed `POST` into another method upstream; and three GraphQL adapter defects: a mutation result reading a private repository with no label (`m3_graphql::a_mutation_result_that_reads_a_private_repository_is_a_sensitive_read`), a fragment chain that overflowed the stack and aborted the daemon, and one query triggering thousands of credentialed lookups ([[ADR-035 GitHub GraphQL and Host-Wide Read Labels as Built]] item 12);
  - policy compilation (5): a plain `[[egress]]` entry compiling to an `#any` permit that disabled method and path rules on the same host ([[ADR-027 Plain Host Grants Carry No L7 Authority]]); record mode allowing forced pushes ([[ADR-024 Formal Gates as Built]]); the org public-sink forbids lost when MCP permits rebuilt the engine ([[ADR-033 Public-Sink Rule as Built]]); repository policy rejecting `[identity]` only when it listed OIDC issuers ([[ADR-034 Device Login as Built]]); a profile's own `filesystem` section ignored in M0;
  - labels (10): host-wide `github.read` raising no label ([[ADR-035 GitHub GraphQL and Host-Wide Read Labels as Built]]); `git.fetch` raising no label ([[ADR-036 Git Fetch Visibility by Anonymous Probe]]); seven gaps from the 2026-09-26 review ([[ADR-040 Label Sources Beyond the Adapters]]); MCP server labels not reaching the agent session ([[ADR-038 MCP Server Sessions Share Agent Labels]]);
  - audit record (3): `cedar-policy` switching serde_json to `preserve_order`, which silently changed the canonical key order of the hash chain; a user process named `Sandbox` able to forge kernel reports; a forgeable skip of the shim's rows by process name ([[ADR-041 Kernel Denials on the Audit Record]]).

  Fuzzing: 26 targets in `code/tests/fuzz/fuzz_targets/`, all in the CI smoke (`ci.yml`, 60 s each) and the nightly job (`fuzz-nightly.yml`, 2 h each, clean seconds totalled per target in each run's summary, not in the repository). The Build Log records four clean nights (2026-09-27 to 09-30) for the 18 earliest targets, about 8 h each by that count (the 2026-10-01 run is not recorded); the six added on 2026-09-30 and `sentinel` and `shim_spec` (2026-10-01) start later. Parsers of sandbox-influenced bytes with property tests but no cargo-fuzz target, against [[CLAUDE]] section 11: `brokerd::kernel_denials::parse` (unified-log lines carrying sandbox-chosen process names and paths; `parse_is_total`) and the MCP relay (`brokerd::mcp::relay::tests`; its framing is fuzzed by `mcp_frame`). The public corpus is `code/tests/bypass-corpus/hosts.toml` (36 host cases, run by `invariants::i6_bypass_corpus_end_to_end`); path, git and L7 cases live only in conformance tests so far. No pentest vendor engaged and no bounty.
- **R4.** `ctl.sock` is mode 0600 in a 0700 directory with a peer-UID check (`code/crates/brokerd/src/proto.rs`) and refused to a sandbox (`m0_categories::cat09_proxy_bypass`). Secrets are `creds::Secret` (zeroized on drop, no `Clone`); minted GitHub and STS credentials live only in broker memory (`code/crates/creds/src/session.rs`, `issuers/aws_sts.rs`); STS sessions default to 15 minutes. Identity tokens never reach the agent, an upstream or the audit log (`m3_identity::d7_the_identity_token_never_reaches_an_upstream`, `m3_login::*`). Gaps: `creds::secrets` reads roots from the keychain, brokerd's environment or a 0600 file, and the M1 real-GitHub run used a file (`~/.config/broker/gh-app.pem`), so "keychain-held roots" is an option, not a rule; brokerd does not call `PR_SET_DUMPABLE` or limit core dumps (only the Linux network bridge is non-dumpable), and no test looks for a canary in a core dump; the conformance probe has a `ptrace` mode that no test runs, so isolation of brokerd's memory rests on design (Linux: PID namespace plus seccomp denying `ptrace` and `process_vm_readv`; macOS: `process-info` only within the sandbox) without an end-to-end test.
- **R5.** Tests: `m3_github::d5_toxic_flow_is_stopped_at_the_public_write`, `m3_graphql::the_toxic_flow_over_graphql_is_stopped_at_the_public_write`, `m3_label_gaps_mcp::*`, `m3_approvals::a_held_write_is_approved_on_the_host_once_and_never_from_inside`. Category 11 (`m4_covert::cat11_covert_channel_bandwidth`, nightly on Linux): query strings ≈81 KB/s, path choice ≈93 B/s, timing ≈0.9 B/s on one laptop, reported in `code/docs/threat-model.md`, never claimed zero. The 2026-09-25 audit found no claim that the broker stops prompt injection; [[M4 Harden and Ship]] asks for a re-check before release. No L2 run ([[L2 Injection Benchmarks]]), so there is no attack-success number yet. The model API exemption ([[ADR-039 Model API Is Not a Rule-of-Two Sink]]) leaves a write path into the user's own provider account by design.
- **R6.** `launcher::backends` has one backend per OS behind a common report; `crates/launcher/src/backends/mod.rs` names the VM tier (Virtualization.framework, Cloud Hypervisor) as phase 2 and the Seatbelt backend reports `vz_available: false`. A change to Seatbelt's unified-log report format would stop `kernel.denied` rows (a record gap, not an enforcement gap) and fail `m4_kernel_denials::kernel_denials_are_on_the_sessions_record` on the macOS runners.
- **R7.** `broker doctor` prints the Landlock ABI and, when unprivileged user namespaces fail, points at the Ubuntu AppArmor restriction (`crates/launcher/src/backends/linux/inner.rs`). `packaging/apparmor/broker-bwrap` is installed by CI when the gate is on; no package installs it for users. `invariants::i2_launch_refuses_when_any_layer_is_missing` covers the required layers.
